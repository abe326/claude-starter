# pickup_cue.py（UserPromptSubmit）・pickup_check.py（Stop）・design_docs_reminder.py（PostToolUse の記録）の手順つきケース。
# run_pickup_cases.py が読む。ケースごとに一時ディレクトリへ模擬プロジェクトを作り、手順を順に流す。
#
# 書式: <期待 none|context|block><TAB><手順><TAB><出力に含む文字列 or -><TAB><フェーズ or -><TAB><備考>
#   期待は「最後の手順」の出力に対して見る（none = 出力なし / context = additionalContext / block = "decision":"block"）
#   フェーズ: - は Sketch（data-phase="Sketch"）。Sketch / Build は概要 HTML の data-phase に書く（旧い値もそのまま書けば読み替わる）。なし は phase マーカーの無い概要 HTML
# 手順は ; 区切り:
#   prompt:<文>        UserPromptSubmit を流す（\n は改行）
#   prompt-long:<字数>  字数ぶんの貼り付け文（「あとで」を含む）を流す
#   prompt-raw:<文>     session_id 付きの JSON に、<文> をそのまま prompt として入れる（< で始まる通知など）
#   touch:<rel>        ファイルを書いて PostToolUse（Write）を流す
#   bash:<rel>         ファイルを書くだけ（PostToolUse を通さない = new.py・close.py 相当）
#   stop / stop-active Stop を流す（stop_hook_active: false / true）
#   stopraw:<文>        Stop に <文> をそのまま流す（壊れた JSON）
#   nosid              以後の手順を session_id なしで流す
#   env:<名前>=<値>     以後の手順に環境変数を足す
# <rel> の略記: 02_打合せ/ → docs/案件/02_打合せ/、open/ → docs/案件/01_タスク管理/open/。ほかはルート相対。
# 模擬プロジェクトの打合せ記録: ok.md（全行に落ち先）/ nodrop.md（決定 1 行に落ち先なし）/ guess.md（→ APP-1）/
#   missing.md（→ APP-09）/ notissue.md（→ 未決 APP-01）/ old.md（## 決定事項・落ち先なし）/ oldcol.md（宿題の旧列「関連タスク ID」）
# 行頭 # と空行は無視。
