# pickup

固い決まりは 1 つだけ。**作業中に出たもの（決定・未決・あとでやること・ハーネス候補）は、必ず「反映済」「タスク」「未決」のどれかに落とす。** 拾ったのにどこにも落ちていない状態で終えない。

- 落ち先の書き方の正本は `docs/案件/02_打合せ/README.md`（打合せ記録・課題の `## 決定`・この報告で共通）
- 未決の正本は課題 md（`docs/案件/01_タスク管理/`、`kind: 課題`）。設計書の本文からは「（未決 QA-01）」で参照する
- 空欄・未記入・未決の多さでは止めない。どのフェーズでも同じ

## 落ち先の書き方（要約）

行末の最後の `→` 以降が落ち先。複数は `、` で区切る。

| 種類 | 書き方 |
|:--|:--|
| 決定（課題） | `→ QA-02`（`new.py … --decided` で起票して閉じた課題。**決定はこれ**） |
| 反映済 | `→ 反映済: 01 §3` / `→ 反映済: ADR-003` / `→ 反映済: 概要 HTML roadmap` / `→ 反映済: 記録のみ（理由）`（課題の `--to` と、旧い記録） |
| 候補（Sketch の間の設計書） | `→ 候補: 05 §3`（まだ足していない文書でもよい。足すときに反映する） |
| タスク | `→ APP-03` |
| 未決 | `→ 未決 QA-01` |
| ハーネス候補 | `→ ハーネス候補 HN-01` |

ID は `[A-Z][A-Z0-9]*-NN`（2 桁以上）。`保留` という落ち先は無い（決まっていないなら未決に起票する）。

## 手順

1. **拾う**。材料は次の 3 つ。4 種（決定・未決・あとでやる・ハーネス候補）に分ける
   - hook の reason・文脈の行（`[拾う]`・`[拾う候補]`・`[落ち先]`）
   - このターンの会話（「決めた」「未定」「あとで」「今後〜しないで」など）
   - 触った打合せ記録の落ち先なしの行
     ```bash
     python3 scripts/check_drops.py --file docs/案件/02_打合せ/<ファイル>
     ```
   拾いものが無ければ「拾いもの: なし」と 1 行書いて終える。
2. **落とす**（1 件ずつ。迷ったら未決）。フェーズは `python3 .claude/hooks/phase.py` で見る
   - **決定** → **課題に書く（決定の正本は課題の `## 決定` だけ）**。起票してすぐ閉じ、打合せ記録の行末に `→ <ID>`
     ```bash
     python3 docs/案件/01_タスク管理/new.py <area> "<問いの形>" --decided "<決定>" --to "反映済: 01 §3"
     ```
     - `--to` はその決定を反映した先。設計書に書いたなら `反映済: NN §n`（設計書の節には「（決定 <ID>）」を添える）、どこにも書かないなら `反映済: 記録のみ（理由）`
     - Sketch の間は 01 §1・§3（目的・スコープ）だけ直接書く。ほかの設計書に関わるものは `--to "候補: NN §n"` で終える（その文書がまだ無くてもよい。「記録のみ」にしない。`sync-design-docs` は回さない）
     - Build では影響マップの候補の節に 1 行（判定は `sync-design-docs` の手順 4）
     - **実装の拾いもの(Stop hook の「実装: …」)は、Build なら `sync-design-docs` スキルを起動して手順 4 の 4 つの問い（選んだ方式・構成 / 置いた境界・約束 / 仮置きしたもの / 採らなかった案）を当てる。**「決まったことが無い」「雛形のままなので書かない」で終えてよいのは、4 つのどれにも当たらないときだけ。仮置きしたもの(方式が未定など)は課題を起票し、候補の設計書の該当節に「（未決 <ID>）」を 1 行書く
     - 会話の中で決まったこと（打合せ記録に無いもの）も同じく課題に起票してすぐ閉じる
   - **未決** → 課題を起票する。Build では関係する設計書の節に「（未決 <ID>）」を 1 つ書く
     ```bash
     python3 docs/案件/01_タスク管理/new.py <area> "<〜するか>" --kind 課題 [--decider SH-02] [--due YYYY-MM-DD]
     ```
   - **あとでやる** → タスクを起票する。期限を言われていれば `--due`（「来週」は日付に直す）
     ```bash
     python3 docs/案件/01_タスク管理/new.py <area> "<題>" [--due YYYY-MM-DD]
     ```
   - **ハーネス候補** → `harness` スキルで `docs/ハーネス台帳.md` に状態「候補」の 1 行を足し、`→ ハーネス候補 HN-NN` と書く。定義（settings・rules・skill・hook・agents）はユーザーの承認まで書かない
3. **ID を写す**。`new.py` の出力の 1 行目が確定した ID。元の行の末尾に `→ <ID>` / `→ 未決 <ID>` で書く。起票前に ID を書かない
4. **確かめる**
   ```bash
   python3 scripts/check_drops.py --file docs/案件/02_打合せ/<触った打合せ記録>
   ```
   落ち先なし 0・ID 不在 0・書式違反 0 になるまで直す。打合せ記録を触っていなければ `python3 scripts/check_drops.py` で全体を見る。
5. **報告は 1〜3 行**
   ```
   拾った N 件: 反映済 a（01 §3 ほか）／ タスク b（APP-03）／ 未決 c（QA-01）／ ハーネス候補 d（HN-01）
   ```
   拾ったが落とさないと判断したものは、理由を 1 行で書く（同じものは hook が再度促さない）。

## 禁止事項

- ID を予想して書く（`new.py` の出力の 1 行目から写す）
- 拾ったものを会話にだけ残して終える（反映済・タスク・未決のどれかに落とす）
- 空欄・未決の多さ・雛形のままの設計書を理由に、作業を止める・ユーザーに枠を埋めさせる・質問を重ねる
- 決まっていないことを `反映済` にする（未決に起票する）
- 1 件のために設計書の節を丸ごと書く（1 行で足りる）
- ハーネス候補を承認なしに settings・rules・skill・hook・agents として定義する（台帳に「候補」で書くまで）
- `保留` を落ち先にする
- 秘密（URL・ID・パスワード）を打合せ記録・課題・報告に書く（`環境情報.md` を参照させる）
