# draft-from-existing

既存のフォルダにスケルトンを入れると、記録の器（概要・現在地・案件情報など）は空欄で入る。中身は**もうフォルダの中にある**ことが多い（README・仕様書・議事録・設定・コード）。
利用者に一から書かせず、Claude が読んで**下書き**を作る。利用者の仕事は、下書きの誤りを直すことだけにする。

## いつ使うか

- `init.py --merge` の「次にやること」にこのスキルが出た（初めてスケルトンを入れたとき）
- new-project スキルで既存フォルダに適用した直後
- 設計書 01 や概要 HTML が空欄のまま、フォルダには資料がある
- 「既存の資料から埋めて」「今あるものから下書きを作って」と言われた

空欄の器が無い（もう書いてある）ところには書かない。上書きはしない。

## 手順

1. **読む範囲を決める**（全部は読まない。目安は合わせて 20 ファイル）
   - ルートの `README*`・`docs/` の索引・既存の設計書や仕様書・議事録の直近数本
   - 設定: `package.json`・`pyproject.toml`・`Dockerfile`・`docker-compose*`・`.github/workflows/`・`*.tf` など、あるものだけ
   - コードは構成（トップのフォルダとエントリポイント）だけ。中身の精読はしない
   - 読まないもの: `.work/`・`.git/`・`node_modules/` などの依存・`環境情報.md` 以外の秘密らしいファイル（`.env`・鍵）
2. **下書きを書く**（空欄のところだけ。各所に「下書き」の印）
   | 書く先 | 中身 | 印 |
   |---|---|---|
   | `docs/設計書/01-概要.md` §1（目的）・§3（スコープ） | 何のための仕事か・どこまでやるか を各 1〜3 行 | 行末に「（下書き: 既存資料から。要確認）」 |
   | `docs/プロジェクト概要.html` 「3. 現在地」 | いま何をしている段階か 1 行（`update-overview` スキルの手順で、マーカーの内側だけ） | 同上 |
   | `案件情報.md` §1・§2 | 関係者のロールと、案件の状態・次の期日（資料に書いてあるものだけ） | 同上 |
   | `環境情報.md` | 環境の一覧（名前・用途）。**値（URL・ID・鍵）は資料にあってもここにだけ書く**。docs には転記しない | 同上 |
   | `.claude/project.json` | 仕組みが固定で読み書きするパス（`work_area_allow`）・中に別の git リポがあるフォルダ（`nested_repos`）。見つかったときだけ | 追記は利用者の承認後（`.claude/` の編集は承認が要る） |
   - コードがある案件は、`docs/設計書/02-構成.md` を足す**候補**として報告する（足すのは承認後に `python3 scripts/add_doc.py 02`）
   - 読んで分かった「決まっていないこと」は課題にする候補として並べる（起票は `pickup` スキルの流儀で、利用者に確認してから）
3. **利用者に聞く**のは、次の 3 点だけを短く
   - 目的とスコープの下書きが合っているか（1 行ずつ見せる）
   - 現在地が合っているか
   - 読んだけれど判断できなかったこと（2〜3 個まで）
4. 直してもらったら「（下書き…）」の印を外し、`01-概要.md` の鮮度メタ行と改訂履歴を更新する。`python3 scripts/check_skeleton.py` で fail=0 を確かめる

## 守ること

- **推測で埋めない**。資料に根拠が無いところは空欄のまま残し、「判断できなかったこと」に回す
- 秘密（URL・ID・パスワード・鍵）は `環境情報.md` と `.env` にだけ書く（`.claude/rules/secrets.md`）。会話の出力にも写さない
- 既存の資料は書き換えない・移動しない。読むだけ
- 下書きは 1 回の作業で終える。長い調査が要りそうなら、どこまで読んだかを報告して区切る

## 関連

- `update-overview` スキル — 概要 HTML のマーカーの内側の書き方
- `update-env-info` スキル — `環境情報.md` / `案件情報.md` の書き方
- `sync-design-docs` スキル — 設計書のメタ行と改訂履歴
- `pickup` スキル — 決まっていないことを課題に落とす
