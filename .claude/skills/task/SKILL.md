# task

作業の正本はタスク md、未決の正本は課題 md（どちらも `docs/案件/01_タスク管理/open/<ID>_タイトル.md`）。起票・クローズ・画面管理・一覧生成は同じフォルダの CLI で行い、手で ID を採番したりファイルを移動したりしない。

- 1 画面の要約（コマンド・タスクと課題の違い・frontmatter・クローズ基準）は `docs/案件/01_タスク管理/README.md`
- スキーマ全欄・本文の雛形（タスク 9 節・課題 7 節）・領域・画面・概要 HTML の自動欄・data.js の契約は同じフォルダの `詳細仕様.md`

## CLI（`docs/案件/01_タスク管理/` で実行）

**読むのは open だけ。** `closed/` は ID で指されたとき（「（決定 QA-03）」など）だけ開く。最近の出来事は `docs/案件/作業ログ/最新.md`（生成物）。

| 操作 | コマンド | 結果 |
|:--|:--|:--|
| 起票 | `python3 new.py <area> "タイトル" [--priority 高] [--owner 名前] [--due YYYY-MM-DD] [--tag x]` | `open/<ID>_タイトル.md` を雛形付きで作る。**出力の 1 行目が確定した ID** |
| 課題として起票 | `python3 new.py <area> "〜するか" --kind 課題 [--decider SH-02] [--due YYYY-MM-DD]` | kind が 課題 の md（7 節） |
| 決定を記録（起票してすぐ閉じる） | `python3 new.py <area> "〜するか" --decided "<決定>" --to "反映済: 01 §3" [--to "APP-03"]` | 課題を作り `## 決定` に 1 行目と落ち先を書いて `closed/` へ。`--to` が無いと何も作らない。**決まったことの正本はここだけ**（打合せ記録・設計書からは ID で指す） |
| 領域を足して起票 | `python3 new.py 新領域 "タイトル" --add-area 新領域:NEW` | `areas.json` に足してから起票 |
| 引数と領域の一覧 | `python3 new.py -h` | 何も作らない |
| クローズ | `python3 close.py <ID>` | `open/` → `closed/` へ移動（付随資料も一緒に）、status を 完了 に |
| 再オープン | `python3 close.py <ID> --reopen` | `closed/` → `open/` へ戻す |
| 画面の追加 | `python3 screen.py new "<名前>" --path /x` | `screens/` に SCR-NN を作る |
| 画面のステータス | `python3 screen.py set SCR-01 実装中` | 未着手 / 実装中 / 確認待ち / 完了 / 保留 |
| 一覧生成 | `python3 build.py` | `data.js` と概要 HTML の自動欄（`task-snapshot`・`open-issues`・`milestones`・`recent-decisions`）を更新 |
| 検査のみ | `python3 build.py --check` | 生成せずに frontmatter の欠落・不正値（`due` の形式を含む）・孤児の添付を報告 |

- 領域（area）の正本は `areas.json` だけ（一覧は `new.py -h`）。未登録の領域では起票せずに止まる。足すときは `--add-area 名前:PREFIX`
- 登録済みのプレフィックス（`APP` など）を area に渡すと、対応する名前に読み替えて続行する
- 引数の誤り（未登録の area・`--due` の形式違い・`--decided` だけで `--to` 無し）は何も作らずに止まる

## 起票の手順

1. `work-placement` か `pickup` スキルで起票と決まっている、またはユーザーの指示があること
2. 領域を選ぶ（`new.py -h`）。タスクか課題かを決める（決めなければ進めない問いなら課題。課題の title は「〜するか」の問いの形）
3. `new.py` で起票し、**出力の 1 行目の ID を写す**。打合せ記録・課題の `## 決定`・設計書の「（未決 <ID>）」にはこの ID を書く。**起票前に ID を予想して書かない**（`APP-1` のような予想 ID は検査が書式違反・ID 不在として出す）
4. 生成された md を Read し、frontmatter を埋める: `status`（未着手 / 進行中 / 方針確定 / 確認待ち / 保留 / 完了）、`priority`（最高 / 高 / 中 / 低）、`screens`（関係する画面 ID の配列。無ければ `[]`）。任意の `due`（期限）・`decider`（課題を決めるロール。実名は書かない）は、分かっているときだけ書く
5. 本文を埋める（分からない節は「未定」と書き、空のまま消さない）。雛形の中身は `詳細仕様.md`

   **タスク（9 節）**

   | # | セクション | 書くこと |
   |:--|:--|:--|
   | 1 | 概要 | 何をするか 1〜3 文 |
   | 2 | 対応の意義 | なぜ今やるか。やらないと何が困るか |
   | 3 | 対応後の変更点 | 利用者・運用者から見て何が変わるか |
   | 4 | 対応計画の概要 | 手順の骨子（箇条書き 3〜7 行） |
   | 5 | 対応計画の詳細 | 具体的な作業・ファイル・コマンド |
   | 6 | 影響・依存 | 他タスク・他システム・関係者への影響と依存 |
   | 7 | 完了条件 | 何をもって完了とするか（検証可能な形で） |
   | 8 | 過去の経緯 | 作業中の判断・試行・却下した案を日付付きで追記していく |
   | 9 | 参照情報 | 関連タスク ID・ADR・証跡パス（`.work/証跡/<ID>_内容/`）・打合せ記録 |

   **課題（7 節）**: 概要 / 論点 / 選択肢（推奨があれば理由 1 行）/ 決着条件（`decider`・`due` と食い違わせない）/ 決定（未決の間は空欄）/ 過去の経緯 / 参照情報

6. `python3 build.py` で一覧と概要 HTML の自動欄を更新する

## クローズの手順

### タスク

1. 「完了条件」のチェックリストを [x] にし（該当しない条件は `- [x] 該当なし: 理由`）、満たしたことを本文（過去の経緯）に日付付きで書く。`close.py` が「完了条件にチェックの無いものがある」と警告したら、揃っているなら [x] に直す。揃わないまま閉じるなら理由と引き継ぎ先（後続タスクの ID）を本文に 1 行
2. 証跡が `.work/証跡/<ID>_内容/` にあるなら「参照情報」にパスを書く
3. `python3 close.py <ID>` → `python3 build.py`
4. フェーズ・方針・ロードマップに効く完了なら `update-overview` スキル、環境・関係者・実名の待ちに効くなら `update-env-info` スキルを続ける

### 課題（決着したとき）

1. `## 決定` の **1 行目に決定内容**（日付・誰が決めたかを括弧で）、2 行目以降に**落ち先を 1 行ずつ**書く。書き方の正本は `docs/案件/02_打合せ/README.md`
   ```markdown
   ## 決定
   対象は本社の正社員のみ（2026-09-30 打合せ / SH-02）
   → 反映済: 01 §3
   → APP-03
   ```
   取り下げなら `→ 取り下げ: 理由` を 1 行
2. `python3 close.py <ID>` → `python3 build.py`。**`## 決定` の 1 行目と落ち先が無い、または落ち先の ID が実在しないと、閉じずに止まる**。足りないものを書いてからやり直す
3. 設計書の本文に「（未決 <ID>）」が残っていれば、落ち先に書いた節だけを直す（`python3 scripts/check_drops.py` が「決着済みの未決を参照」と出す）
4. 実装が要る決定は、閉じたあとで別にタスクを起票し、落ち先に `→ <タスクID>` を足す

## 画面（screens）の付け方

- UI を持つプロジェクトで、タスクがどの画面に関係するかを `screens:` に SCR-ID で書く（`screens: [SCR-01, SCR-03]`）
- 画面が無ければ `screen.py new` で先に作る。画面の実装状況は `screen.py set` で変える（タスクの status とは別）
- UI を持たないプロジェクトでは `screens: []` のままでよい

## 禁止事項

- ID を手で採番する・起票前に予想して書く（`new.py` の出力の 1 行目から写す）
- md を手で `closed/` へ移す（CLI を使う。課題の決着条件を飛ばすことになる）
- 課題を `## 決定` の 1 行目と落ち先なしで閉じようとする
- frontmatter に規定外の値を書く（`build.py --check` が検出する）
- 本文の節のうち空のものを消す（「未定」と書いて残す）
- タスク md・課題 md に秘密の実値や実名を書く（`環境情報.md`・`案件情報.md` を参照させる）
- `data.js`・`index.html`・概要 HTML の自動欄を手で編集する（`build.py` の生成物）
