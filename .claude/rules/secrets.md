# 秘密情報の取り扱い

## 原則

**実値（URL・プロジェクト ID・ユーザー名・パスワード・API キー・トークン・接続文字列・秘密鍵）は、`環境情報.md` と `.env` にだけ書く。** どちらもルート直下・Git 管理外。

| 何を | どこに | 備考 |
|:--|:--|:--|
| 環境の URL・アカウント・資格情報・アクセス手段 | `環境情報.md` | 実値を書く正本。`update-env-info` スキルで更新 |
| アプリが読む環境変数の値 | `.env` | 変数名と意味は `.env.example`、値の所在は `環境情報.md` §5 |
| 関係者の氏名・未公開の日程 | `案件情報.md` | 値ではなく状態の要約。秘密の実値は書かない |
| 受領した一次資料（契約書・決算書・名簿等） | `.work/機密/<タスクID>_内容/` | `.work/` ごと Git 管理外 |

## 転記の禁止

次の場所には**値を写さない**。参照が要るときは「`環境情報.md` §n 参照」と書く。

- `docs/` 配下すべて（概要 HTML・設計書・タスク md・打合せ記録・確認依頼一覧）
- `CLAUDE.md`・`README.md`・`.claude/` 配下
- 会話の出力（要約・報告・確認依頼の文面）。値が要る場面では「`環境情報.md` の §n に書いてある」と示す
- コミットメッセージ・PR 本文

## 検査が見る範囲と形

- 範囲: `docs/` 配下の md・html すべて（打合せ記録・タスク md・確認依頼一覧を含む）、`CLAUDE.md`・`README.md`・`CHANGELOG.md`、`.claude/` 配下の md。`環境情報.md`・`案件情報.md`・`.env*`・`.work/` は見ない
- 形: 既知のトークン形式（`AKIA…`・`ghp_…`・`sk-…`・`xox…-`・秘密鍵の BEGIN 行）、スキームを問わない URL の資格情報（`<scheme>://<user>:<pw>@`）、`password=`・`token:`・`パスワード：` などの key=value（記号入りの値も）。伏せ字・プレースホルダ・環境変数名・「環境情報.md 参照」は除く
- `python3 scripts/check_skeleton.py --secrets` で単独に回せる（全フェーズで NG。出すのはファイルと行番号だけ）。誤検知の行は、同じ行に `<!-- secret-scan: ok 理由 -->` と書いて外す

## `.gitignore` の必須行

生成時に `.gitignore` へ入っている。消さない。

```
.work/
環境情報.md
案件情報.md
.env
.env.*
!.env.example
.mcp.json
.claude/settings.local.json
```

`.mcp.json` と `.claude/settings.local.json` は MCP サーバーのトークンや個人の許可設定を含みうるため除外している。共有したい MCP 設定は値を環境変数参照にしたうえで別途判断する。

## 疑わしいときの扱い

- 「秘密かどうか分からない値」は秘密として扱う（`環境情報.md` に置き、`docs/` には書かない）
- 秘密を `docs/` やタスク md に書いてしまったと気づいたら、履歴に残る前に取り除き、既にコミット済みなら値のローテーションを検討する
- ログ・スクショ・ダンプに秘密が写り込むことがある。`.work/証跡/` へ置く前に目視で確認する

## 関連

- `環境情報.md` — 実値の正本（Git 管理外）
- `.env.example` — 変数名と意味の見本
- `.claude/skills/update-env-info/SKILL.md` — 環境・関係者・日程の更新手順
- `.claude/rules/work-area.md` — `.work/機密/` の扱い
