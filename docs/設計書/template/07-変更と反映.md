# 07 変更と反映 — 変更をどう反映するか
> 最終更新: 2026-10-01（初版。雛形のまま）／ 対象: —
> 作成: 2026-10-01 ／ 位置づけ: 環境・変更の流れ・データの移行・反映・戻し・監視の正本 ／ 対象読者: Claude Code・担当者
> 扱わないもの: 接続先・コマンドの実値 → `環境情報.md` §4、手順本文 → `runbook/`、監視条件の閾値 → `09-非機能と障害時.md` §6

## 0. 位置づけ

「変更がどう本番に届き、どう戻るか」の方針。手順の本文は `runbook/`（1 操作 1 ファイル）に置き、本書は方針と索引だけを持つ。

`未決`・`提案` の項目を根拠に「方針に反する」と指摘しない。`決定` に実装が反していれば実装側を直す（`04-原則.md` §3）。

## 1. 環境と変更の単位

変更の単位は案件ごとに違う（例: 開発ならブランチ、SaaS/インフラの管理なら変更申請 1 件）。

| 環境 | 変更の単位（例: ブランチ） | 誰が触れる（SH-xx） | 反映経路 | 正本 | 状態 |
|:--|:--|:--|:--|:--|:--|
| ローカル・検証 | 任意 | SH-01 | — | `環境情報.md` §2.x | 決定 |
| | | | | `環境情報.md` §2.x | |

（例。開発）`本番 | main | SH-01（承認: SH-02） | CI から自動 | 環境情報.md §2.1 | 提案`
（例。SaaS/インフラの管理）`本番 | 変更申請 1 件 | SH-01（承認: SH-02） | 管理コンソールから手動 | 環境情報.md §2.1 | 提案`

## 2. ローカル開発

| 項目 | 内容 | 状態 |
|:--|:--|:--|
| ねらい | 本番と同じ構成を手元で再現し、壊しても戻せる | |
| 構成 | （例）本体・データ・外部サービスの疑似環境 の 3 役 | |
| 不変則 | （例）本番のデータを手元に持ち込まない | |
| 初回セットアップの骨子 | 手順は `README.md`（ルート）。値は `環境情報.md` §4 | |
| 日常操作 | 起動・停止・ログの見方 | |
| 検証 | 06 §7 のテストを手元で回す | |
| トラブルシュート | よくある症状 → 見るところ | |

## 3. 変更の流れ

起票 → 変更の単位に分ける（例: ブランチ）→ 実装・設定 → ゲート（06 §5）→ レビュー（06 §4）→ 確定（例: マージ）→ 反映（§5）。

| 項目 | 規約 | 状態 |
|:--|:--|:--|
| 起票 | タスク md（`task` スキル）。ID を変更の単位・記録に書く（例: ブランチ名・コミット・PR） | 決定 |
| 変更の単位（例: ブランチ） | | |
| 記録（例: コミット） | | |
| レビュー依頼（例: PR） | | |
| CHANGELOG | `CHANGELOG.md`（ルート）。利用者に見える変更だけ | 決定 |

（例。開発）`変更の単位（ブランチ） | <タスクID>/<短い英語>。main へ直接 push しない | 提案`
（例。SaaS/インフラの管理）`変更の単位 | 変更申請書 1 件 = 1 単位。申請 → 検証環境 → 本番設定 | 提案`

## 5. 反映（例: デプロイ）

| 環境 | 骨子 | 前提権限 | 事後確認 | 失敗時 | 状態 |
|:--|:--|:--|:--|:--|:--|
| | | | | `runbook/` | |

（例。開発）`本番 | main への merge で CI が配備 | CI の反映用資格情報（環境情報.md §5） | ヘルスチェック・主要画面 | runbook/戻し.md | 提案`
（例。SaaS/インフラの管理）`本番 | 変更申請の承認後、管理コンソールで設定を反映 | 管理コンソールの操作権限（環境情報.md §5） | 主要機能の動作確認 | runbook/戻し.md | 提案`
