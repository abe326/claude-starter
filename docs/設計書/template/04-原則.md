## 0. 位置づけ

機能に依らず常に効かせる**原則**（P-xx）の正本。`docs/プロジェクト概要.html` の principles はここの要約（3〜7 個）。個別の判断は `decisions/` の ADR に残し、本書は「どちらを選ぶか」の基準だけを持つ。

`未決`・`提案` の項目を根拠に「方針に反する」と指摘しない。`決定` に実装が反していれば実装側を直す（§3）。

## 1. 原則

条文は一文。「なぜ」と「守れているかの見方」を必ず添える（見方が書けない原則は原則ではなく好み）。

| ID | 条文 | なぜ | 守れているかの見方 | 関連 INV | 状態 |
|:--|:--|:--|:--|:--|:--|
| P-01 | 秘密の実値は `環境情報.md` と `.env` にだけ置く | 共有前提の `docs/` に値が混ざると回収できない | `docs/` を grep して実値が出ない | INV-01 | 決定 |
| | | | | | |

（例）`P-02 | 利用者に見える文面は 08 §5・§6 の正本から出す | 場当たりの文面が用語を壊す | 画面文言の grep が 08 の固定文と一致する | — | 提案`
（例。運用保守・PM 業務）`P-03 | 変更は戻せる形にしてから進める（例: 開発ならブランチとロールバック手順、SaaS の管理なら変更前の設定の控え） | 戻せないと縮退・障害時に手が止まる | 07 §6 に戻し方の記載がある | INV-02 | 提案`

## 2. 緊張関係

原則同士がぶつかる場面と、どちらを優先するか。優先の根拠は ADR に置く。

| A vs B | 場面 | 優先 | 根拠 ADR |
|:--|:--|:--|:--|
| | | | |

（例）`P-01（秘密は環境情報.md）vs 作業の速さ | 会話出力で値を見たい | P-01。「環境情報.md §n に書いた」と伝える | ADR-000`

## 3. 迷ったときの決め方

1. **原則（§1）** に照らす。当てはまる原則があればそれに従う
2. 無ければ **ADR（`decisions/`）** を探す。同じ論点の判断が既にあればそれに従う
3. それでも無ければ **タスク md** に判断と理由を書いて進める。複数タスク・複数領域に効くなら ADR へ昇格する
4. **実装・設定が原則に反していたら、その実装・設定側を直す。** 乖離はタスク化して追跡し、原則は動かさない
5. **原則そのものを変えるなら、先に §4 に変遷を書く。** 旧案を否定した理由を残さずに変えない

## 4. 方針の変遷

否定済みの旧案が復活するのを防ぐための記録。**日付と決定主体を書くのは本書ではここだけ**。新しい順。

| 論点 | 旧 | 中間 | 新 | なぜ | 日付 | 決定主体 |
|:--|:--|:--|:--|:--|:--|:--|
| | | | | | | |

（例）`権限の単位 | 個人単位 | — | 組織単位 | 個人単位だと異動のたびに付け直しが要る | YYYY-MM-DD | SH-02`

## 5. 未決

未決は課題 md が正本（`docs/案件/01_タスク管理/`、kind=課題）。本文からは「（未決 QA-01）」で参照する。本書に関わる未決は `python3 scripts/check_drops.py --refs 04` で一覧
