# runbook — 手で行う操作の手順

1 操作 1 ファイル。方針は `../07-変更と反映.md`（索引は同書 §8）。値（URL・ID・資格情報・接続先）は書かず、`環境情報.md` の節番号で示す。

## 型

```markdown
# runbook: <操作名>

根拠タスク: XXX-00 ／ 最後に実際に通した日: YYYY-MM-DD（対象・所要時間）

## 権限の前提

- （例）本番デプロイ権限（`環境情報.md` §3）

## いつ使うか

- （例）版を上げたあとのヘルスチェックが失敗した

## 手順

### A. <段の名前>（所要の目安）

1. コマンドや操作。値は `環境情報.md` §n を見る
2. …

### B. …

## 確認すること

- （例）ヘルスチェックの版が戻し先の値になっている

## 失敗したとき

| 症状 | 見るところ |
|:--|:--|
| | |

## 落とし穴

- 🔴 （例）片方だけ戻すと検査が落ちる。A と B は必ず対で行う
```

## 索引

`07-変更と反映.md` §8 と同じ内容を保つ。

| 操作名 | ファイル | 最後に通した日 | 所要時間 | 前提権限 |
|:--|:--|:--|:--|:--|
| | | | | |

（例）`戻し（ロールバック） | 戻し.md | YYYY-MM-DD | 5 分 | 本番デプロイ権限`

## 運用

- **通したら日付を更新する**（冒頭の「最後に実際に通した日」と、本索引・07 §8 の「最後に通した日」）。長く通していない runbook は信用しない
- 手順が実態とずれていたら、その場で直す。日付別・`_v2` ファイルは作らない
- 値は書かない。`環境情報.md` §n を参照する（`.claude/rules/secrets.md`）
- 新しい runbook を足したら、本索引と 07 §8 に同じ行を足す
- 障害時の利用者向け文面は `../08-利用者の運用.md` §5 からコピーする。runbook に独自の文面を書かない
