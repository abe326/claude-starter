# 02_打合せ/ — 打合せ記録

打合せ 1 回につき 1 ファイル。ファイル名は `YYYYMMDD_タイトル.md`（例: `20260101_キックオフ.md`）。
**決定・未決・宿題の各行に「落ち先」を書く**（どこに反映したか・どのタスク／課題にしたか）。落ち先の無い行は検査が数え、作業の区切りで hook が 1 回促す。拾って落とす手順は `pickup` スキル。

## 書式

```markdown
# YYYY-MM-DD タイトル

- 出席: （役割で書く。顧客の個人名を出すかは 案件情報.md §1.4 の連絡ルールに従う）
- 目的:

## 決定
- 対象は本社の正社員のみ → QA-02
- 承認は 1 段階 → QA-03
- 切り替えは 2027-04 → QA-04、APP-02

## 未決
- 派遣社員を対象に含めるか → 未決 QA-01
- 既存データをどこまで移すか → 未決 OPS-01

## 宿題
| 誰が | 何を | 期限 | 落ち先 |
|:--|:--|:--|:--|
| 当方 | 移行範囲の案を出す | 2026-10-07 | → OPS-02 |

## 議論の要点
- （決定・未決に至らなかった話。落ち先は要らない）

## 次回
- 日程・議題
```

- **落ち先が要るのは `## 決定` `## 未決` の箇条と `## 宿題` の表の行だけ**。議論の要点・次回には要らない
- 決定・未決は箇条（1 行 1 件。あとから 1 行ずつ足しやすい）、宿題は「誰が・期限」が要るので表
- 旧形式の見出し `## 決定事項` と宿題の「関連タスク ID」列もそのまま読める（v1.2.0 より前の記録を書き直さなくてよい）
- `## 要約` の下の `### 決定事項` `### 未決` `### 宿題` のような H3 の区切りも読める（会議ツールの要約をそのまま貼る形）

## 落ち先の書き方（打合せ記録・課題の `## 決定`・pickup の報告で共通。ここが正本）

行末の**最後の `→` 以降**を落ち先とみなす。複数は `、` で区切る。

| 種類 | 書き方 | 機械が確かめること |
|:--|:--|:--|
| 決定（課題に書いた。**新しく書くときはこれ**） | `→ QA-02` | 課題 md がある（`new.py … --decided` で起票して閉じたもの） |
| 反映済（正本に書いた。旧い書き方もそのまま受ける） | `→ 反映済: 01 §3` / `→ 反映済: ADR-003` / `→ 反映済: 概要 HTML roadmap` / `→ 反映済: CLAUDE.md §6` | `NN` で始まれば `docs/設計書/NN-*.md` がある。`ADR-NNN` は `decisions/ADR-NNN-*.md` がある |
| 反映済（この記録そのものが正本） | `→ 反映済: 記録のみ（理由）` | 括弧の理由がある |
| 候補（Sketch の間の設計書） | `→ 候補: 05 §3` | `NN` の設計書がある、**またはまだ足していないが `docs/設計書/template/` にある**（足すときに反映する先）。Sketch の間は落ちた扱い。Build では「候補のまま」と情報で出る |
| ハーネス候補 | `→ ハーネス候補 HN-01` | `.claude/ハーネス台帳.md` の表に ID がある |
| タスク | `→ APP-03` | タスク md（open か closed）がある |
| 未決 | `→ 未決 QA-01` | 課題 md（`kind: 課題`）がある |
| 取り下げ（課題の `## 決定` だけ） | `→ 取り下げ: 理由` | 理由がある |

- ID は `[A-Z][A-Z0-9]*-NN`（2 桁以上）。`APP-1` のような 1 桁は書式違反（起票前に予想した ID の典型）
- 落ち先なし = `→` が無い、または `→` の後が空・`?`・`未定`
- **「保留」という落ち先は作らない。** 決まっていないなら課題に起票して `→ 未決 <ID>`

### 起票してから ID を書く

1. 行を書く（この時点では落ち先なしでよい）
2. 起票が要るものを `python3 docs/案件/01_タスク管理/new.py <area> "<題>" [--kind 課題] [--due YYYY-MM-DD]` で起票する
3. **出力の 1 行目の ID**を行末に `→ <ID>` / `→ 未決 <ID>` で書く。起票前に ID を予想して書かない
4. 確かめる: `python3 scripts/check_drops.py --file docs/案件/02_打合せ/<このファイル>`（落ち先なし 0・ID 不在 0）

## 運用

- 各行に落ち先を書く（書式は上の表）。落ち先の無い行は `scripts/check_drops.py` が数える。作業の区切りで `pickup` スキル
- **決まったことの正本は課題の `## 決定`。** 決定ごとに `new.py <area> "<問いの形>" --decided "<決定>" --to …` で課題を起票してすぐ閉じ、行末に `→ <ID>` と書く。設計に効くものは設計書の該当節にも「（決定 <ID>）」付きで 1 行（Sketch の間は 01 だけ。ほかは課題の `--to` に `候補: NN §n` と書く）
- 宿題の期限は起票時に `--due` で移す。「来週」のような相対の言い方は日付に直す
- 相手に確認・判断を頼むことが生まれたら → 課題を起票し、相手向けの文面が要れば `../確認依頼一覧.md` に **ID 付きで** 1 行
- 実名の待ち・公開しない日程が変わったら `案件情報.md` を `update-env-info` スキルで更新する
- 文字起こし全文はここに置かず、要約だけを残す。全文が要るなら `.work/証跡/YYYYMMDD_打合せ全文/` へ（`.claude/rules/work-area.md`）
- 秘密（URL・ID・パスワード）は書かない
