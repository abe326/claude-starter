# claude-starter タスク・課題・画面管理ツール

作業の正本（タスク md）と、決めてほしいこと（課題 md）と、画面の進捗を **Markdown ＋ Python（標準ライブラリのみ）** で管理する。
md のスキーマ・本文の雛形・画面・概要 HTML との連動・data.js の契約は **`詳細仕様.md`** にある（ここは 1 画面の要約）。
起票・クローズは `task` スキル。ID は手で採番しない。

## よく使うコマンド（このフォルダで実行）

```bash
python3 new.py 横断 "ログイン画面のバリデーション追加" [--priority 高] [--owner 名前] [--due 2026-10-07]
python3 new.py 横断 "派遣社員を対象に含めるか" --kind 課題 [--decider SH-02] [--due 2026-10-07]
python3 close.py QA-03            # open/ → closed/（付随資料も一緒に）。--reopen で戻す
python3 build.py [--check]        # data.js と概要 HTML の自動欄を更新（--check は検証だけ）
python3 new.py -h                 # 引数と登録済みの領域の一覧（何も作らない）
```

- `new.py` の 1 行目は確定した ID。**打合せ記録・落ち先にはこの ID を写す**（起票前に予想して書かない）
- 未登録の領域では止まる。領域は `areas.json` に足すか `--add-area 名前:PREFIX`
- 閲覧は `index.html` をブラウザで開く（書き込みは CLI で行う）

## タスクと課題の違い

| | タスク | 課題 |
|---|---|---|
| 何か | 実行して完了させる作業 | 意思決定・すり合わせが必要な未決事項（**未決の正本**） |
| いつ閉じるか | 下の「クローズ基準」が揃ったら | 決着したら。`## 決定` の 1 行目と落ち先（`→ 反映済: 01 §3` / `→ APP-03`）が無いと閉じられない |
| どこに出るか | 一覧の領域別・エピック別 | 一覧の課題バンドと、概要 HTML の「決めてほしいこと」 |

実装が要る決定は、課題を閉じてから別にタスクを起票する。

## frontmatter

| 欄 | 必須 | 中身 |
|---|:-:|---|
| `id` `title` `area` | ✅ | ID（`new.py` が採番）・タイトル（課題は問いの形）・領域（`areas.json` の名前） |
| `status` | ✅ | `未着手` / `進行中` / `方針確定` / `確認待ち` / `保留` / `完了` |
| `priority` | ✅ | `最高` / `高` / `中` / `低` |
| `kind` | — | `タスク`（省略時）/ `課題` |
| `due` | — | 期限 `YYYY-MM-DD`（タスク・課題共通）。書いたものだけが一覧と概要 HTML「次の節目」に出る |
| `decider` | — | 課題を決めるロール（`SH-02` など。実名は書かない） |
| `epic` `owner` `tags` `screens` `source` | — | 括り・担当・タグ・関連画面 ID・起点の打合せ記録名 |
| `created` `updated` `closed` | — | 日付。`close.py` が書き換える |

## 補助資料の置き場

- 比較表・スクショなど、タスクの補助資料は**タスク md と同じフォルダ**に `<ID>_内容_YYYYMMDD.拡張子` で併置する（`close.py` が一緒に動かす）
- 大きいもの・生データ・機密は `.work/証跡/<ID>_内容/`（Git 管理外）に置き、タスク md から「証跡: <パス>」で名指しする

## タスクのクローズ基準（プロジェクトで書き換える）

コード変更を伴うタスクは、次の**3条件**が揃ったらクローズする（`close.py <ID>`）:

1. **対象環境へ適用済み** — 例: 開発環境へデプロイ済み
2. **確認者の確認が取れた** — 確認者はプロジェクトで定める
3. **正本へ反映済み** — 環境情報・設計書・台帳など、プロジェクトが正本と定めるものへ反映

- 確認は口頭アスクではなく、**環境に適用して実機で動作を見てもらう方式**を基本とし、確認待ちを理由に
  タスクを open のまま滞留させない。実機確認の見どころ・残論点は、クローズ時に本文へ記録するか後続タスクへ引き継ぐ
- コード変更を伴わないタスク（調査・ドキュメントのみ等）は条件 2 のみでクローズ可
- タスク md の「完了条件」はチェックリスト。揃ったら `[x]`、該当しない条件は `- [x] 該当なし: 理由`。
  `[ ]` が残ったまま `close.py` を実行すると警告が出る（閉じるのは止めない）

> この節と `new.py` の本文テンプレート「完了条件（クローズ3条件）」は、プロジェクト開始時に
> 具体的な環境名・確認者・正本の名前に書き換える。

`詳細仕様.md` — md のスキーマ（全欄）・本文の雛形（タスク 9 節・課題 7 節）・領域と ID のプレフィックス・
画面（`screens/`・`screen.py`）・概要 HTML の自動欄（`task-snapshot`・`open-issues`・`milestones`・`recent-decisions`）・data.js の仕様。
