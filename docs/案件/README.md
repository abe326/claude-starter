# docs/案件/ — 共有記録

このプロジェクトで「いま何をしていて、何を決め、相手に何を頼んでいるか」を残す場所。**Git 管理対象で共有する前提**。秘密（URL・ID・パスワード・鍵）と受領した一次資料は置かない（`.claude/rules/secrets.md`・`.claude/rules/work-area.md`）。

## 構成

| パス | 役割 | 更新の仕方 |
|:--|:--|:--|
| `01_タスク管理/` | **作業と未決の正本**。タスク md・課題 md（`open/` `closed/`。決まっていないことは課題に起票する）、画面（`screens/`）、CLI（`new.py` `close.py` `screen.py` `build.py`）、一覧（`index.html` `data.js`）、領域定義（`areas.json`） | `task` スキル。手順は `01_タスク管理/README.md` |
| `02_打合せ/` | 打合せ記録。`YYYYMMDD_タイトル.md`。決定・未決・宿題・次回を残す | 打合せ後に 1 ファイル。**決定・未決・宿題の各行に落ち先**（`→ 反映済: 01 §3` / `→ APP-03` / `→ 未決 QA-01`。書き方は `02_打合せ/README.md`、手順は `pickup` スキル） |
| `確認依頼一覧.md` | 相手（発注側・顧客・レビュアー）に確認・判断してほしいことの一覧（相手向けの文面）。片付いたら履歴節へ | 依頼が生まれたら 1 行（**課題かタスクの ID 必須**）。回答を得たら課題を閉じてから `[x]` にして履歴へ |

## 資料の置き方

- 作業の経緯・判断はタスク md 本文（過去の経緯）へ追記する
- 落ち先の検査: `python3 scripts/check_drops.py`（落ち先なし・ID 不在・決着済みの未決参照・確認依頼の ID・期限切れ）
- タスクに付随する成果物（提出資料・サンプル・残す価値のあるスクショ）はタスク md と同じフォルダに `<ID>_内容_YYYYMMDD.拡張子` で併置する
- 大きい・機密・生データはここに置かず `.work/証跡/<ID>_内容/`（Git 管理外）に置き、タスク md からパスで参照する
- 複数タスク・複数領域に効く判断は `docs/設計書/decisions/` の ADR へ昇格する

詳細は `.claude/rules/docs-management.md`。
