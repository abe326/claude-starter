# claude-starter ドキュメント

`docs/` は **Git 管理対象で共有する前提**。秘密（URL・ID・パスワード・鍵）は書かない（`.claude/rules/secrets.md`）。

**人が見るものはシンプルに、AI が読むものは詳細に。** 人が見る画面（概要 HTML・一覧・作業ログ）は正本から生成し、1 行で言い切って ID で辿れるようにする。AI が読む正本（タスク・課題の本文、設計書）には経緯と理由まで書く。1 つの事柄の正本は 1 か所だけ。

## 索引

| パス | 内容 | 更新の仕方 |
|:--|:--|:--|
| `プロジェクト概要.html` | 目的・思想・現在地（フェーズ・決めてほしいこと・次の節目・直近の決定）・将来対応・構成図と設計書の入口・更新履歴。**人が最初に読む 1 枚** | `update-overview` スキル（決めてほしいこと・次の節目・直近の決定・タスクの状況は `build.py` が自動で書く） |
| `案件/01_タスク管理/` | **あとでやること（タスク）と、決まっていないこと・決まったこと（課題）の正本**。一覧は `index.html` | `task` スキル（`new.py`・`close.py`・`build.py`） |
| `案件/02_打合せ/` | いつ・誰と・何を話したか（一次記録）。事実は各行の落ち先の ID へ | `pickup` スキル |
| `案件/作業ログ/` | 出来事の時系列（生成物。手で書かない）。`最新.md` が直近 14 日、`README.md` が月ごとの索引 | `build.py` と作業の区切りの hook が作り直す |
| `設計書/` | 今どうなっているか・方針。最初は `01-概要.md` だけで、ほかは `設計書/template/` から必要になったら足す。索引と「いつ読むか」は `設計書/README.md` | `sync-design-docs` スキル、足すときは `python3 scripts/add_doc.py <番号>` |
| `ハーネス台帳.md` | AI への指示（skill・hook・ルール・許可）の候補と定義済み。スケルトンへ返したいものは「返す」列 | `harness` スキル |

運用ルール（置き場・秘密・作業領域）は `.claude/rules/` にある。設計書は「方針」、`.claude/rules/` は「日々のルール」と役割を分ける。

## フェーズ

フェーズは `Sketch` / `Build` の 2 つ。正本は `プロジェクト概要.html` の「3. 現在地」（`data-phase`）で、生成直後は Sketch。
Sketch は情報を集めている段階で、拾って落とすことだけを促す。外部へ情報を出し始めた・設計が始まったら Build にし、文書の追随・鮮度まで見る。止めるのは形と秘密と置き場だけで、どちらでも空欄・未記入では止めない。
厳しさの表は文書に複製しない。`python3 .claude/hooks/phase.py --table` で見る。切り替えは AI が判断して行い（確認は挟まない。報告で 1 行伝える）、`update-overview` スキルで行う。

## 読む順番

### 作業を再開する人（毎セッション）

1. SessionStart の注入（フェーズ・open のタスク件数・最近の出来事の件数・設計書の要確認）
2. `案件/作業ログ/最新.md` — 直近 14 日に何があったか。古いことは `案件/作業ログ/README.md` で月を絞る
3. `プロジェクト概要.html` の「3. 現在地」（決めてほしいこと・次の節目・直近の決定）
4. タスク・課題は `open/` だけを読む。`closed/` は ID で指されたときだけ開く
5. 作業種別ごとに読む設計書は `設計書/README.md` の「知りたいこと → 正本」

### 初めて触る人

1. `プロジェクト概要.html` — 目的・原則・いまどこにいるか
2. `設計書/01-概要.md` — 何のための仕事か
3. `案件/作業ログ/README.md` — これまでの流れ（月ごと）
4. `案件/01_タスク管理/index.html` — いま何が動いているか
5. `README.md`（ルート）— 動かし方

### 設計を変える人

1. 決まっていることを確かめる: 課題の `## 決定`（概要 HTML の「直近の決定」から ID で辿る）と `設計書/decisions/`
2. 新しく決めたら課題に書く（その場で決まったものも `new.py … --decided` で起票してすぐ閉じる）。長い理由は `設計書/decisions/ADR-000-テンプレート.md` の型で ADR にし、課題から指す
3. 設計書には「今どうなっているか」を書き、「（決定 QA-03）」のように ID を指す（`sync-design-docs` スキル）
