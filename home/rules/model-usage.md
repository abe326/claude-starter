# モデルとサブエージェントの使い分け

定額プラン（週次の利用枠がある前提）でも従量課金でも、既定を低コスト側に寄せ、要るところだけ上げる。

## サブエージェントの既定は sonnet

- `settings.json` の `env` に `CLAUDE_CODE_SUBAGENT_MODEL=sonnet` を入れてある（claude-starter の `settings.base.json`）。サブエージェント・Agent Teams のチームメイト・Workflow のエージェントは、モデルを省略すると sonnet で動く。**省略してもメインのモデルは継承されない**
- モデルが決まる順: 呼び出し時の `model` ＞ 定義ファイルの `model` ＞ 定義ファイルの `model: inherit`（メインを継承）＞ この環境変数
- 階層は `haiku` < `sonnet` < `opus` / `fable`。**上限はメイン。** メインより上位のモデルをサブエージェントに指定しない
- **上げたいときだけ、呼び出し時に明示する**

| サブエージェントに渡す作業 | 指定するモデル |
|---|---|
| 機械的・定型（変換・整形・grep 的探索・集計・一覧化・リネーム） | `haiku` |
| 調査・読解・要約・コード追跡・広範囲の探索・Web 調査 | 省略（＝ `sonnet`） |
| 設計判断・曖昧さの解決・複数制約を跨ぐ実装 | メインと同じモデルを明示（`opus` / `fable`） |

## 書き忘れで高いモデルが走らないように

- **組み込みの Explore／Plan を呼ぶときは `model` を必ず書く**（調査・読解は `sonnet`、ファイル名やキーワードを探すだけなら `haiku`）。Explore は省略するとメインのモデルを継承し、上の環境変数が効かない（実測）。Plan も同様に扱う
- **`.claude/agents/` に定義を作るときは frontmatter に `model` を必ず書く。** メインを継承させるなら `model: inherit` と書く。コメントに「継承」と書いただけでは継承されない
  - 「継承させたい」と「書き忘れた」が見分けられないため。設計書で決めても、定義ファイルに書かなければ効かない。書いたかどうかはテストなどで機械的に確かめる

## 本数を絞る

- **サブエージェントは、`smart-orchestrator` スキルの委譲判断に当てはまるときだけ使う。** 1 本起動するごとに白紙からシステムプロンプトなどを読み込み直す（実測で十数万トークンのキャッシュ書き込み）。数回のツール呼び出しで済む作業は、渡すとかえって高くつく
- **並列は、独立した大きな作業に限る。** チームは小さく保ち、終わったら止める。コストは、本数を必要最小限にしたうえで 1 本あたりの単価（モデルと effort）で下げる
- 「調べて」系の Web 調査（検索と取得を何回も回して要約する）は、メインで回さず sonnet のサブエージェント 1 本に渡し、要点と出典だけ受け取る。1〜2 回の検索で済む事実確認はメインでよい

## メインを上げるのは行き詰まったときだけ

- 目安: 同じ不具合・同じ論点で 2 回以上やり直しになった／判断が複数ファイル・複数制約に跨り出力が一貫しない／ユーザーが指示した
- 上げるのはメイン（`/model opus` など）。**サブエージェントは追随しない**ので、上げたいときは呼び出し時に明示する
