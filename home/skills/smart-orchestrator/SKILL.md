# Smart Orchestrator

大きな独立作業をサブエージェントへ委譲し、トークンの最適配分とメインコンテキストの温存を両立する。
**全作業の委譲ではない。委譲はコンテキスト再構築・報告往復のオーバーヘッドを伴うため、割に合う場面だけ委譲する。**

## 委譲判断（最重要）

| 委譲する | 委譲しない |
|---------|-----------|
| 真に独立で並列化できる大きな作業（無関係モジュールの同時実装、広い multi-file 調査） | 数回のツールコールで終わる作業（少数ファイルの読み書き・軽い検索・小さな修正） |
| 出力が大きくメインコンテキストを汚す作業（ログ精読、大量ファイルの読み込み・要約） | 検証・レビュー・ダブルチェック（メインループで行う） |
| 定型・反復のバッチ作業（N 件の変換・整形・集計） | 1 つの小さな仕事を複数エージェントに分割すること |

原則: **1 エージェントで足りるなら 1 エージェント**。並列数は必要最小限（明示指示がない限り大量並列はしない）。

## モデル選択

ルール本体は `~/.claude/rules/starter/model-usage.md`（claude-starter）。要点:

- **サブエージェントは既定で sonnet。** `settings.json` の `env` の `CLAUDE_CODE_SUBAGENT_MODEL=sonnet` により、モデルを省略するとメインが opus / fable でも sonnet で動く。**省略してもメインのモデルは継承されない**
- **上限はメインのモデル。** メインより上位のモデルをサブエージェントに指定しない
- **作業に見合う最小のモデルを選ぶ**（`haiku` < `sonnet` < `opus` / `fable`）
  - 機械的・定型（変換・整形・grep 的探索・定型集計・一覧化）→ `haiku` を明示
  - 調査・読解・要約・コード追跡・広範囲の探索 → 省略（＝ sonnet）
  - 設計判断・曖昧さの解決・複数制約を跨ぐ実装 → メインと同じモデルを明示（`opus` / `fable`）
- 軽量モデルは推論力が低い — 2 ステップ以上の判断が必要なら軽量化しない。品質が要るところを削らないための下げ方をする
- 定義ファイル（`.claude/agents/*.md`）でメインを継承させるときは `model: inherit` と書く（書かなければ sonnet）
- **組み込みの Explore は例外で、省略するとメインを継承する（実測）。Plan も同様に扱う。** 呼ぶときは `model` を必ず書く（調査は `sonnet`、単純な探索は `haiku`）

## 運用ルール

1. **依存のない委譲は同一メッセージで並列起動**する
2. **指示は最初に完全に書く** — 目的・制約・成果物の形式まで一度で渡し、起動→待機→再指示のループを避ける
3. **委譲したら任せる** — 報告された結果を再導出・やり直ししない（明白な誤りがある場合のみ介入）
4. **大きな成果物はファイルへ** — サブエージェントには「成果はスクラッチパッド（システムプロンプト記載のパス）に保存し、返答は要点のみ」と指示する
5. **エージェント間のデータ受け渡しはファイル経由** — サブエージェントは独立コンテキストで、互いの出力を直接見られない
6. **プロジェクトの安全規約を伝播する** — 対象プロジェクトに本番操作禁止・push 禁止等のルールがある場合、その制約をサブエージェントのプロンプトに明記して渡す
7. **ユーザーへの報告はサマリ＋成果物パス** — 詳細を転記しない

## プロジェクト固有スキルとの併用

対象プロジェクトに実装フロー系のスキル（レビュー体制・検証手順・エージェントチーム等）がある場合は**そちらの型を優先**し、本スキルは委譲判断とモデル選択の原則としてのみ適用する。

## よくある失敗

- 小タスクを律儀に委譲してかえってトークンを浪費する（→ 委譲判断の表に戻る）
- 検証をサブエージェントに投げる（→ 検証はメインループの責務）
- 前エージェントの出力を口頭転記で次エージェントへ渡す（→ ファイル経由にする）
- 安全規約を伝えずに委譲し、サブエージェントが push や本番操作を試みる（→ 制約を必ずプロンプトに明記）
- 設計判断を任せるのにモデルを省略し、sonnet で走らせてしまう（→ `opus` / `fable` を明示）
